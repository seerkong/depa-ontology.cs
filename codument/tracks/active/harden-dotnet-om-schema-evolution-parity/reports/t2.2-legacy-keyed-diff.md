# T2.2 Detect-only initialization and keyed diff

## Implementation

- `InitializeSchemaV2Async` inspects `::relations` and `::columns` before any
  write. Its default `DetectOnly` option returns a structured warning and
  leaves legacy `om_property` / `om_edge` shapes untouched.
- `LegacyHandling=Upgrade` uses Cozo's single-program `:replace` operation for
  each legacy temporal relation. This is the same mechanism used by Bun: it
  copies existing rows into the bi-temporal shape with `ASSERT` validity and
  transaction time, then initializes the remaining schema in the same write
  transaction. This avoids unsupported system DDL such as `::remove` inside a
  transaction.
- `DiffSchemaVersionsV2Async` and `DiffCurrentAgainstSnapshotV2Async` return
  `SchemaKeyedDiff`, keyed by relation and each relation's schema key columns.
  It includes the C# snapshot's behavior, permission, alias, and existential
  relations in addition to type, attribute, and relation definitions.

## Constraint discovered and resolved

Cozo system DDL (`::remove` / `:create`) cannot run through an active native
transaction. The first implementation attempt surfaced this as `expect script
to contain only a single program`. The final implementation does not use that
path: `:replace` is a single Datalog program accepted by the same transaction,
so explicit upgrade remains atomically committed with its preservation writes.
