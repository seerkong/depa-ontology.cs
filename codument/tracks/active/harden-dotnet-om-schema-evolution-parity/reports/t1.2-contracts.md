# T1.2 Typed V2 schema evolution contracts

## Delivered boundary

Added additive, immutable V2 contract types without changing the legacy schema
execution path:

- `SchemaInitializationOptions` defaults to `DetectOnly` legacy handling.
- `SchemaMigrationV2Options` defaults `Strict` to `true`.
- `SchemaRollbackV2Options` defaults to strict and non-forced execution.
- V2 initialization, migration, and rollback result types carry immutable
  `SchemaDiagnostic` collections.
- `SchemaKeyedDiff` groups immutable per-definition changes by snapshot table,
  preserving the broader C# snapshot surface rather than narrowing it to the
  Bun subset.
- `SchemaMigrationV2Input` defensively clones supplied `JsonElement` steps,
  so a migration plan is stable after construction.

The legacy `SchemaMigrationSpec`, initialization, migration, rollback, and
coarse-diff methods remain behaviorally unchanged. Their facade comments make
the compatibility boundary explicit. They are not marked obsolete yet because
no safe executable V2 replacement exists before T2.1/T2.2 implement strict
preflight, atomic application, detect-only initialization, and keyed-diff
production.

## Deferred work

This leaf intentionally does not add V2 execution facade methods that could
accidentally dispatch to the non-atomic legacy implementation. T2.1 will wire
the declared inputs/results to transactional preflight and rollback logic;
T2.2 will provide detection/upgrade and calculate the keyed diff.
