# T2.1 Atomic V2 migration and rollback

## Implementation

`SchemaLogic` now exposes V2-only execution paths behind the contracts added
in T1.2:

- `ApplySchemaMigrationV2Async` opens one write transaction before reading the
  schema state. It performs structural preflight and strict checks before
  legacy migration writes, then commits only after migration log, snapshots,
  schema state, and definitions all succeed.
- Strict preflight rejects incompatible stored values for `changeAttribute`
  and rejects a new required attribute when matching existing entities lack a
  value. An unsupported later step is also rejected before writes.
- `RollbackSchemaV2Async` restores the target snapshot inside one transaction,
  validates all entities against that restored schema before commit, aborts on
  strict diagnostics, and permits the explicit `Force` path to commit while
  returning those diagnostics.
- The legacy migration and rollback methods retain their legacy behavior;
  only the additive V2 facade methods call the new atomic paths.
