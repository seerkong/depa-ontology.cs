# T3.1.1 Jint Outer-Guard Scheduling Correction

**Verdict: PASS**

## Diagnosis

The parent/inheritance composition itself did not reproduce a runtime hang. A
pre-change diagnostic full harness completed it in 1.006 seconds and completed
the whole harness in 183.495 seconds. The old test-only outer guard nevertheless
implemented its three-second deadline with `Task.WhenAny(task, Task.Delay(...))`.
When the timer and the observed task complete near the same scheduler turn, that
manual winner selection can report the timer branch even though the observed work
has completed. This is a test-guard scheduling race, not a reason to relax any
Jint execution limit or action behavior.

## Applied Change

Only `cozo-lib-dotnet/tests/OmScriptingJintContractTests.cs` changed.

- Replaced the hand-rolled `Task.WhenAny`/`Task.Delay` race with
  `Task.WaitAsync`, retaining the same default three-second outer deadline and
  the caller-provided timeout diagnostic.
- Added `AssertOuterGuardPreservesCompletionAndTimeoutSemanticsAsync`, which
  proves that an asynchronously-continuable completed task succeeds and that a
  deliberately never-completing task still receives the supplied timeout.
- Did not modify Jint's script timeout, statement, recursion, memory or
  cancellation limits; did not modify external watchdogs, action assertions or
  runtime source.
