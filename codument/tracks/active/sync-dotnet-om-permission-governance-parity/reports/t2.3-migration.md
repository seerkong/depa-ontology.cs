# T2.3 Legacy Seed and Facade Migration

## Migration

- The legacy `subject->project` seed in `Program.cs` now uses the declared `assigned_project` relation and a real `admin -> proj1` edge.
- The legacy `subject->person` read setup now uses `permission_can_read_person`, with a concrete `u1 -> p1` witness. The field inspection and deny-precedence policies now also declare canonical relations with actual witnesses.
- `PermissionGovernanceParityFixtures` characterizes the hard cut directly: a stored `subject->project` path is invalid with `unknown_relation` and cannot produce an allow result.
- The fixture preserves the typed async facade contract by verifying that permission seed/check operations leave a schema snapshot readable with the same checksum and that a cancelled `CheckAccessAsync` call throws `OperationCanceledException`.

No permissive normalization or explanatory-only fallback was added. `CheckAccessAsync` continues to use the strict evaluator and the existing public facade forwarding.
