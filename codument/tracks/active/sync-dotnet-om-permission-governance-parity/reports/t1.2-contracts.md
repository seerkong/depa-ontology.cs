# T1.2 Typed Permission Result Contracts

## Contract Surface

- `CheckAccessResult` preserves its existing `Allow` and `Explanation` constructor surface, and now exposes immutable `FieldVisibility` and `PolicyEvaluations` projections.
- Per-policy entries contain a typed witness diagnostic, per-predicate ABAC diagnostics, and deterministic diagnostic codes. `Explanation.evaluatedPolicies` and `Explanation.fieldVisibility` serialize the same projections.
- A path referencing an undefined relation, a malformed path, an unsupported ABAC operator, or a malformed ABAC reference is `Invalid` and cannot contribute an allow result. Missing subject/resource entities return a typed fail-closed result with `missing_subject` or `missing_resource`. The fixture covers the unknown relation, unsupported operator, malformed reference, and missing-subject cases.

## TDD Evidence

1. The fixture first referenced `CheckAccessResult.FieldVisibility`, `CheckAccessResult.PolicyEvaluations`, and `PermissionEvaluationStatus`; the pre-implementation build failed with `CS1061`/`CS0103` for those missing public contracts.
2. After implementation, `dotnet build Cozo.DotNet.Om.Tests.csproj --no-restore` succeeds with 0 warnings and 0 errors.
3. `dotnet run --no-build --project Cozo.DotNet.Om.Tests.csproj` reaches the intended T1.1 red light: an allow policy with a declared but unwitnessed `permission_owns` path still returns `Allow=True`. Its typed witness status is `Unmatched` with `witness_unavailable`, and its explanation reports lowercase `"unmatched"`, so the permissive behavior is explicitly visible rather than presented as a witness.

## Deferred To P2

T1.2 does not traverse graph edges, emit actual witness hops, resolve AsOf graph/property state, evaluate temporal ABAC comparators, or apply field-hide effects. P2 must make unmatched paths and deferred predicates strictly deny, then populate the typed witness and field-visibility projections with the real evaluation results.
