# T1.3 Historical Alias Storage

## Result

PASS

`ExistentialRuleLogic` now expands canonical runtime names to every compatible
historical stored name before evaluating an existential rule:

- body and target entity types include aliases that resolve to each canonical
  type and descendant;
- relations include aliases that resolve to the canonical relation;
- each `where` predicate accepts the canonical attribute and compatible aliases
  from every applicable body type scope.

The expansion is deduplicated and ordinal-sorted, preserving deterministic
violation output. Rule storage is still read first, so the existing missing
rule-storage no-init behavior remains unchanged.

## Regression

`ExistentialGovernanceParityFixtures` now persists legacy source and target
entities, a legacy relation edge, and a legacy `tier_legacy` property before
the canonical schema names and aliases are introduced. A post-rename canonical
rule recognizes the historically satisfied entity and reports only the legacy
entity whose matching legacy property has no edge.
