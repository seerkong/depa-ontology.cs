# T1.2 Typed Public Contracts

## Contract

`TypeParentPatch` makes D5=C explicit:

- `Keep`: retain the stored parent when redefining a type.
- `Set(parentType)`: resolve and replace the parent.
- `Clear`: remove the parent.

`DefineTypePatchInput` carries that patch separately from the legacy nullable
`DefineTypeAsync` overload. The old overload therefore remains source and
behavior compatible: null still means preserve, never clear.

The model rejects an empty `Set` parent and rejects a parent payload on `Keep`
or `Clear`. It intentionally does not add a public facade yet; that belongs to
T2.1 alongside the actual type-update semantics, traversal, constraint
validation, and value inference facades.
